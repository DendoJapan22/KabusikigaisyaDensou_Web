## 1. このサイトが達成すべきこと

**ページの唯一の仕事**：設立直後・1名体制であることを差し引いても取引・応募して問題ない会社だと、元請の担当者に判断させること。

**最大の設計上の困難**：会社は新しく、社員は1人で、施工実績は社名義でまだ無い。
この状態で信頼を作れる材料は **代表者個人の30年** しかない。したがって、

> **設立年ではなく、職人としての経験年数を最上位に置く。**（contents.md 3-1）

これはコピーの方針であると同時に**デザインの方針**でもある。会社の規模を演出する要素（大げさなロゴ、抽象的な企業理念、社員の集合写真風レイアウト、「私たちは」という複数形）は、実態とのギャップを生んで逆効果になるため一切使わない。**個人の技能を見せる方向に全振りする。**

**読み手ごとの優先**

| 読み手 | 求めているもの | デザイン上の対応 |
| --- | --- | --- |
| 元請の担当者 | 実在性・資格・守備範囲 | ヒーロー直下の証拠バー、会社概要の情報密度 |
| 求職者 | 条件・続けられるか | 採用ページを配色ごと切り替えて別動線化 |
| 個人客 | 料金・頼みやすさ | 電話番号の常時可視化、料金表の明快さ |

## 2. 参照元をどう使うか

### 2-1. 残すもの

1. **左上の白い切り欠きプレート** — 写真を切り欠いて白面が差し込まれる形。右下角だけ大きく丸い。低コストで最も記憶に残る形状
2. **縦書きコピー × 横長写真の直交** — 横書きにすると同業他社サイト（青と白のテンプレート）と見分けがつかなくなる。ここが唯一の差別化
3. **ヘッダー右側の2段構成** — 参照元は上段に副次的な読み手（キャリア採用／障がい者採用）を逃していた。**本件も構造が同じ**：上段に「採用情報」「個人のお客様へ」＝主動線（B2B）から分離すべき2つの別読者を置く。この対応は偶然ではなく、同じ問題への同じ解
4. **ヘッダーに背景バーを敷かない**

### 2-2. 捨てるもの

- **雰囲気だけのヒーロー**。参照元は社名だけで信用が成立する企業なので、詩的なコピー1本で成立する。本件は成立しない。ヒーローに**証拠バー**を必ず併置する（参照元には無い要素）
- **エントリー中心のCTA設計**。この業種の一次接触は電話。電話番号を `tel:` リンクで常時可視にする

### 2-3. 縦書きを採用してよいかの判断

小規模事業者に明朝縦組みを使うと、気取って見える危険がある。**回避条件は「コピーが具体的であること」の一点。**

- ✅ 「住まいの電気を、／三十年つくってきた。」— 事実の記述。職人の言葉として成立する
- ❌ 「街の灯りは、／誰かが守っている。」— 主語が曖昧な詩。1名の会社が言うと空虚になる

**縦書きには漢数字を使う**（三十年）。算用数字は縦組みで倒れるか縦中横処理が必要になり、明朝の縦線の流れを乱す。
**算用数字は証拠バー側で使う**（`30年 / 1都4県`）。ここはコンデンス欧文で、走査されるべき数字として機能させる。役割を分ける。

そのまま `:root` に貼ること。ここにない色を使わない。

```css

  --blue-500: #2E6BA8;  /* リンク・副CTA */

  --ink-40: rgba(8,25,43,.40);
  --rule:   rgba(8,25,43,.12);  /* 表組みの罫 */

  /* 書体 */
  --font-display: "Shippori Mincho", "Noto Serif JP", "游明朝", serif;
  --font-body:    "Zen Kaku Gothic New", "Noto Sans JP", sans-serif;
  --font-util:    "Barlow Condensed", "Zen Kaku Gothic New", sans-serif;

  --s-1: 8px;  --s-2: 16px; --s-3: 24px; --s-4: 32px;
  --s-5: 48px; --s-6: 64px; --s-7: 96px; --s-8: 128px;

```

**書体の役割分担（厳守）**

- `--font-display`（明朝）：ヒーローの縦書きコピー、各ページのタイトル、代表者メッセージの引用部**のみ**。本文には使わない

**銅色の使用制限**：Signature の縦罫、リンクの下線、小さなアイコン、数値の単位、見出し脇の短い罫。
**ボタンの塗り・大きな面には絶対に使わない。**

### 5-3. 縦書きの実装

```css
.hero__copy {
  writing-mode: vertical-rl;   /* 右→左に列が進む */
  text-orientation: mixed;
  font-family: var(--font-display);
  font-weight: 300;
  font-size: clamp(2.25rem, 4.4vw, 4rem);
  letter-spacing: .14em;       /* 縦組みでは字送り＝縦方向 */
  line-height: 2.05;           /* 縦組みでは行送り＝列の間隔 */
  color: #fff;
  text-shadow: 0 1px 24px rgba(8,25,43,.35);
}
```

**落とし穴（必ず守ること）**

- `vertical-rl` では DOM の順番がそのまま右→左になる。列を逆に書かない
- 列の分割は `<br>` で行う。CSS の自動折り返しに任せると端末ごとに崩れる
- `line-height` が列間、`letter-spacing` が字間になる。横組みと役割が入れ替わる
- 句読点「、」「。」は縦組みで右上に寄る。**正しい挙動なので直さない**
- **算用数字はコピーに入れない**（漢数字を使う。§2-3）。やむを得ず2桁を入れる場合のみ `<span style="text-combine-upright:all">30</span>`。3桁以上は横倒しになる
- 長音符「ー」は自動で回転する。触らない
- Safari で `writing-mode` 要素に `transform: translate()` を掛けると文字が滲む。位置決めは `left`/`top` で行う
- `text-align` は効かない。揃えは `align-items` / `justify-content` で行う

### 5-4. キャッチコピー案

2列・各列 7〜10文字が最も収まる。contents.md 3-1 の3案を縦組み用に整形したもの。

- **A案**　`住まいの電気を、` / `三十年つくってきた。` — 実績と経験年数が一文に入る。**初期実装値**
- **B案**　`配線から空調まで、` / `一人でやり切る。` — 一社完結の訴求。1名体制を弱点でなく速さとして提示
- **C案**　`電気のことなら、` / `まるごと引き受ける。` — 守備範囲の広さ

### 5-5. Signature：「導線」

このサイトが記憶される唯一の要素。**銅線＝電線の実材料**を線に置き換えている。

コピーの右側に **1px の縦罫**。色 `--copper`、不透明度 .55。コピー上端から下端＋64px まで。
ページロード時、罫を**上から下へ光が1度だけ流れる**（通電の一瞬）。通過後にコピーが右列→左列の順でフェードイン。

```css
.hero__rule {
  position: absolute; width: 1px;
  background: rgba(184,115,51,.55);
  overflow: hidden;
}
.hero__rule::after {
  content: ""; position: absolute; inset-inline: 0;
  height: 88px;
  background: linear-gradient(180deg, transparent, #E8A96A, transparent);
  animation: current 1400ms var(--ease) 200ms 1 both;
}
@keyframes current { from { top: -88px; } to { top: 100%; } }

@media (prefers-reduced-motion: reduce) {
  .hero__rule::after { display: none; }
  .hero__copy { opacity: 1; animation: none; }
}
```

**制約**：**1回だけ**。ループさせない。スクロールで再生させない。他要素に流用しない。
サイト内の他のアニメーションは `opacity` のフェードのみに限る。

## 6. 下層ページのテンプレート

9ページを3種のテンプレートに収める。新規テンプレートを増やさない。

### T-A：一覧型 — `/service/` `/works/` `/area/` `/voice/`

- ページヘッダー：`--mist` 地、高さ 220px。タイトル（明朝 40px）＋ 英字ラベル（`--font-util`、`--copper`）＋ パンくず
- 本体：カードグリッド。`> 1200px` で3列、`900–1199px` で2列、`< 640px` で1列。`gap: var(--s-4)`
- カード：`border: 1px solid var(--rule); border-radius: 4px;` 影なし。hover で `border-color: var(--copper)` のみ変化
- `/works/` は絞り込み UI（工事種別 × 物件種別 × エリア）をグリッド上部に。**ピル型のトグル**で、選択時 `--navy-900` 反転

### T-B：記事型 — `/company/` `/service/work/` `/price/`

- 本文コンテナ `max-width: var(--wrap);` 、本文カラムは 720px
- 見出し h2：明朝 30px、左に幅 32px・太さ 2px の銅色罫
- **表組みが主役のページ**（会社概要・料金）：`border-collapse: collapse;` 横罫のみ `1px solid var(--rule)`、縦罫なし。ラベル列 `width: 240px; background: var(--mist);`
- 数値・登録番号・電話は `--font-util`
- `/company/` の代表者メッセージ：本文幅を 640px に絞り、明朝 18px、`line-height: 2.1`。左に代表者写真（正方形 280px、角丸なし）

### T-C：採用 — `/recruit/`

読み手が全く異なるため、**地色を反転させて別動線であることを視覚的に宣言する。**

- ページ全体の背景を `--mist`、カード類を `--paper`
- ヘッダーの「採用情報」ピルを選択状態（`background: var(--navy-900); color: #fff;`）にする
- 給与・勤務時間・休日は**表組みではなくカード3枚で大きく出す**（`--font-util` 40px）。求職者はここしか見ない
- CTA は「応募する」。共通CTAブロックの文言だけ差し替える
- 「現在1名体制」は隠さない方針（contents.md 3-9）。代表者写真を大きく使い、誰と働くかを明示する

### T-D：フォーム — `/contact/`

- 最上部に電話番号（`--font-util` 48px）。フォームより先に置く
- 種別分岐（法人／個人／採用応募）は**ラジオではなく3枚の大きなカード選択**。選択後に該当項目だけ表示
- 入力欄：`height: 52px; border: 1px solid var(--rule); border-radius: 4px;` focus で `border-color: var(--blue-500)` ＋ `outline: 2px solid var(--copper); outline-offset: 2px;`
- 必須ラベルは `--copper` の小さな文字。赤は使わない（サイト内に赤が無いため浮く）
- 写真添付欄あり（contents.md 3-10）。ドラッグ&ドロップ対応、複数可

## 7. レスポンシブ

| ブレークポイント | 挙動 |
| --- | --- |
| `>= 1200px` | 仕様どおり |
| `900–1199px` | ナビ `gap` 24px、CTA `padding` 22px、プレート 232×96。証拠バーは2×2 |
| `< 900px` | ナビをハンバーガーに格納。ヘッダーには**電話アイコンだけ残す**。ヒーローB案は上下分割へ |
| `< 640px` | 下記 |

**モバイル（< 640px）**

- **縦書きは維持する。** ここを横書きに落とすと差別化が消える
- コピー：`font-size: clamp(1.75rem, 8.5vw, 2.5rem); letter-spacing: .1em; line-height: 1.9;`
- 位置：`left: auto; right: 8%; top: 20%;`（右寄せに変更。親指の可視域を空ける）
- 写真：`object-position: 62% 45%;`
- プレート：`width: 190px; height: 78px; border-radius: 0 0 28px 0;`
- スクリム左端を `.66` → `.74` に強める
- 証拠バー：横スクロールさせず、2×2 のグリッドに。数値 24px
- **下部固定バー**（`position: fixed; bottom: 0; height: 60px;`）：左半分「電話する」（`--navy-900`）、右半分「お問い合わせ」（`--blue-500`）。この業種のモバイル流入は電話に直結させる

## 8. 写真の要件と加工

contents.md 3-4 のとおり、写真は**掲載可否と加工が未解決**。実装側では以下を前提に組む。

**技術要件**

- 最低 2400×1600px。`<picture>` で AVIF → WebP → JPEG
- ヒーロー画像に `fetchpriority="high"`。`loading="lazy"` は付けない（LCP要素）
- 一覧のカード画像は `loading="lazy"` ＋ `width`/`height` 属性で CLS を防ぐ

**A案（人物写真）を使う場合の条件**

- 被写体は画面の**右 2/3**。左 1/3 はコピーのために空ける
- 作業に集中している瞬間。カメラ目線・整列した写真は使わない
- **保護具（ヘルメット・絶縁手袋・安全帯）が正しく着用されていること。** 着用が不完全な写真は電気工事会社のサイトでは致命的。該当する場合は差し替えを進言する

**要マスキング（contents.md 3-4）**

建物名の銘板 / 電力量計の製造番号 / 車両ナンバー / 集合ポストの部屋番号 / スクリーンショット由来のUI・ステータスバー。
→ ぼかしではなく**単色ベタで塗り潰す**。ぼかしは「隠している」印象が残り、施工写真の信頼性を下げる。

**alt テキスト**

具体的に書く。「制御盤の主幹ブレーカーを施工する様子」。「作業風景」のような空虚な記述は不可。

## 9. 品質基準（実装完了の判定条件）

- [ ] 縦書きが Safari / Chrome / Firefox / iOS Safari で同じ列順・同じ字間で表示される
- [ ] ヒーローが `data-hero` 属性1つで A案 / B案 に切り替わる
- [ ] 証拠バーが、埋まっている項目数（2〜4）に応じて均等割りされ、空セルが出ない

- [ ] コピーと写真のコントラスト比が 4.5:1 以上（スクリム込みで実測）

- [ ] フォームの各入力に `<label>` が紐づいている（`placeholder` でラベルを代用しない）

## 10. やってはいけないこと

AI がデフォルトで生成しがちで、この設計と衝突するもの。

- ヒーローにグラデーションボタン、光る枠線、ガラス風のぼかしパネル（glassmorphism）を足す
- 写真に視差効果（parallax）を掛ける
- セクションに `01 / 02 / 03` の連番を振る（**例外**：`/service/work/` の施工の流れだけは実際に手順なので連番可）
- 銅色を面として広く使う、または3色目のアクセントを増やす
- 明朝体を本文に使う
- 通電アニメーション以外の動きを足す
- 白いプレートの4隅を丸める、影を付ける
- 縦書きコピーをモバイルで横書きに変える
- **会社を実態より大きく見せる表現**：抽象的な企業理念、「私たちのチーム」、ストックフォトのオフィス風景、社員数を匂わせるレイアウト
- **未確定の情報をプレースホルダで出す**：登録番号「第○○号」、実績「◯◯件」等。埋まらない項目はブロックごと出さない
