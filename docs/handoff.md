## 2. 絶対に守る制約

### AI生成画像を使ってはいけない箇所

1. **代表者の顔写真**（実在の人物。生成した顔は経歴の捏造になる）
2. **施工事例として提示する写真**（自社実績としての虚偽表示。サイトに「実際の現場から」と明記済み）

AIは電気工事の細部（盤内のバー配置、渡り線、端子処理、ケーブルの色分け、保護具）を
ほぼ確実に誤る。一般客は気づかないが、**このサイトの最重要ターゲットである元請・同業者は
一目で見抜く。**

### 生成画像に共通して入れてはいけない要素

人物・顔・手 / 配線・端子台・分電盤内部のクローズアップ / 文字・ロゴ・看板・ナンバープレート /
過剰な彩度・HDR・レンズフレア・ネオン

### その他

- `docs/contents.md` / `docs/design.md` は**クライアント支給の原本。上書き禁止**
  （現行仕様は `docs/site-contents.md` / `docs/site-design.md` に別途記述）
- コミットメッセージ・PR・コードに**モデル識別子を書かない**
- **PRは明示的な依頼があるまで作らない**
- 公開ブランチ `claude/website-construction-qsimq3` に直接コミット＆プッシュ
  （ユーザー承認済み・都度確認不要）

## 4. デザイン上の決定事項（勝手に変えないこと）

### CTAは3種類だけ

| 種類 | 見た目 | 用途 | クラス |
|---|---|---|---|
| Primary | 黄ベタ＋紺文字・高さ56px・角丸8px | 最終アクション。1画面に1つまで | `.btn-primary` |
| Secondary | 枠線ボタン（紺地用は `--light`） | ページ遷移 | `.btn-secondary` |
| Text link | 下線＋`::after`の「→」 | 補足リンク | `.text-link` |

旧 `.btn-solid` `.btn-form` は廃止済み。新しいボタンを足すときは必ずこの3種から選ぶ。

### 見出しフォーマット

全セクション「英字小見出し（黄・字間.26em）＋ 日本語見出し28px」。
`.section__label` は `aria-hidden="true"`（読み上げでは冗長なので）。

### 装飾は「意味のあるもの」だけ

P2で抽象装飾（fx-moon / fx-rings / fx-wave / fx-streams）を**全て撤去した**。
意味のない装飾はテンプレート感＝チープさに直結する、という判断。

現在残している装飾とその意味：

- **電球のエッジなぞり**（選ばれる理由の背景）＝通電して灯る
- **蛇行する電線 powerline**（事業内容）＝配線
- **夜景＋分電盤 night-grid**（最終CTA）＝街の灯りとその裏側
- **ガラスパネル fx-glass**（事業内容×3・ご案内×1）＝図面が重なるイメージ
- **稲妻バッジ・職人線画**＝ブランド素材（/service/ でも使用）

`assets/img/fx-moon.* fx-rings.* fx-wave.* fx-streams.* fx-pendant.*`
`bulb-edison.* denkyuu-real.*` は**現在どこからも参照されていない**（削除可否はユーザー未確認）。

## 5. 検証のやりかた（重要・毎回これをやる）

### ローカルサーバ

```bash
# サイト（頻繁に死ぬので都度起動しなおす）
(setsid python3 -m http.server 8341 >/dev/null 2>&1 &)

# 日本語フォント配信（CORSヘッダ必須）
(setsid python3 <scratchpad>/corssrv.py >/dev/null 2>&1 &)   # :8343
```

### ⚠️ ヘッドレスChromiumはGoogle Fontsに到達できない

この環境の Chromium はプロキシを経由しないため `fonts.googleapis.com` が
`ERR_CONNECTION_RESET` になる（curl は `$HTTPS_PROXY` 経由で通る）。

**日本語Webフォントが無いと縦書きのメトリクスが壊れ、「文字が重なって崩れている」ように見える。**
一度これで存在しないバグを追いかけた。必ずローカルフォントを注入して検証すること：

```python
pg.add_style_tag(url='http://localhost:8343/fonts-local.css')
pg.wait_for_function("document.fonts.status === 'loaded'")
```

フォント一式（woff2 490個＋書き換え済みCSS）は scratchpad の `fonts/` にある。
**コンテナが消えたら再取得が必要**：`curl` で Google Fonts CSS を取得 → gstatic の URL を
ローカルに書き換え → CORSヘッダ付きサーバから配信（CORS無しだと跨オリジンで弾かれ
`document.fonts` が 0 のままになる）。

### 横スクロール検証は5点で

**390 / 910 / 1024 / 1140 / 1440 px**。
1440とスマホだけ見て中間幅のはみ出しを2回見逃した実績がある。

### CSSキャッシュ

GitHub Pages はCSSを10分キャッシュする。**変更したら必ず全7ページの `?v=N` をバンプ**：

```bash
sed -i 's/style\.css?v=41/style.css?v=42/g' index.html area/index.html company/index.html \
  contact/index.html recruit/index.html service/index.html service/work/index.html
```

## 6. 繰り返し踏んだ罠（次も踏む可能性が高い）

| 罠 | 症状 | 対処 |
|---|---|---|
| `mix-blend-mode` がスタッキングコンテキストに閉じ込められる | 黒地が紺に溶けず四角く見える | `transform`/`z-index` を持つ要素**自身**に blend を載せる |
| `aspect-ratio` + `min-height` | min-height が比率経由で min-width に転移し、中間幅ではみ出す | 該当幅帯で `aspect-ratio: auto` |
| 負の `z-index` の `::before` が祖先の背景の裏に消える | 装飾が見えない | 親に `isolation: isolate` |
| CSS詳細度で基底ルールに負ける | 指定が効かない（紺地に紺文字など） | セレクタを1段深くして勝たせる（例：`.insight .insight__heading`） |
| `vector-effect: non-scaling-stroke` + `stroke-dasharray` | **Safariだけ**なぞりが壊れる | 使用禁止。線幅を表示倍率から逆算してSVG座標で指定 |
| `.is-echo-host`（JSが付与）が inline-block | 見出しが横並びになる | `display: block` で打ち消し |

## 7. 未解決の最重要課題：**写真の質**

「チープに見える」原因を数値で分析した結果、**装飾ではなく実写13枚が根本原因**だった。

| 指標 | 最小 | 最大 | 開き |
|---|---|---|---|
| 鮮鋭度 | 45（配管） | 6,637（室外機） | **147倍** |
| 彩度 | 0.03（ほぼ白黒） | 0.45 | **15倍** |
| 平均輝度 | 95 | 160 | 65段階 |

同じ会社が撮ったとは思えないバラつき。加えて全て「白い壁の前の機器」のスマホスナップで、
構図・光が作られていない。**装飾を高級にするほど、中身とのギャップでチープさが増す**構造。

### 提案済みで未着手の対策（優先順）

1. **全13枚のトーン統一現像**（明るさ・彩度・粒子感を揃える）— 撮り直し不要・こちらで実施可能・効果大
2. **撮り直し**（本命）— スマホでよい。夕方〜夜の現場で「機器」ではなく
   「作業している手元と灯り」を撮る。撮り方の具体指示は出せる

## 10. 仕事の進め方（このプロジェクトで学んだこと）

- **言葉で伝わらなければ動くものを見せる**。ポータル構想の説明が伝わらず、
  プロトタイプを作って初めて話が進んだ
- **見た目の不満は必ず数値で原因を特定してから直す**。輝度・彩度・鮮鋭度・
  コントラスト実測・ページ高さの実測。感覚で当てにいかない
- **「Chromiumで動く≠実機で動く」**。Safari非互換で一度作り直している
- ユーザーは細部までよく見ている。「もう少しだけ」という要望には
  控えめに応えるより一段はっきり応えたほうが当たる（透過素材の濃度で経験）
