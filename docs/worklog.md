## 2. 守り続けている制約

### AI生成画像を使ってはいけない箇所

1. **代表者の顔写真**（`/company/` `/recruit/`）— 実在の人物。生成した顔を載せるのは経歴の捏造にあたる
2. **施工事例として提示するすべての写真**（`/service/` の工事メニューおよびトップの「対応可能な工事内容」）— 自社実績としての虚偽表示になる。サイトに「実際の現場から」と明記している

加えて実務上、AIは電気工事の細部（盤内のバー配置、渡り線、端子処理、ケーブルの色分け、保護具の着用）をほぼ確実に誤る。一般の閲覧者は気づかないが、**このサイトの最重要ターゲットである元請・同業者は一目で見抜く。**

### 生成画像に共通して入れてはいけない要素

- 人物・顔・手（すべて）
- 配線・端子台・分電盤内部のクローズアップ
- 文字・ロゴ・看板・ナンバープレート
- 過剰な彩度、HDR、レンズフレア、ネオン、サイバーパンク調

### その他

- `docs/contents.md` / `docs/design.md` はクライアント支給の原本。上書きしない
  （現行サイトの仕様は `docs/site-contents.md` / `docs/site-design.md` に別途記述）
- コミットメッセージ・PR・コードにモデル識別子を書かない

## 4. 主要な実装

### 4-1. ヒーロー

12.4秒のタイムラプス動画（`hero-dusk.mp4` 1.75MB / `.webm` 1.26MB）。
`autoplay muted playsinline preload="auto"`、**ループさせず最後のコマで止める**。
`prefers-reduced-motion` と `navigator.connection.saveData` では動画を外してポスター画像に。

縦書き明朝のコピー「住まいの電気を、／三十年つくってきた。」（数字は漢数字）。
下に信頼バー3項目（カウントアップあり。値が2未満のものはスキップ）。

### 4-2. パワーライン（事業内容）

スクロールに合わせて電線が引かれ、電子が先行し、通過した項目の写真が左右交互に浮かび上がる。

- DOMの実測（`getBoundingClientRect`）からSVGパスを生成。角は45°で面取り
- `getTotalLength()` / `stroke-dasharray` / `stroke-dashoffset` で描画量を制御
- `getPointAtLength()` で先端の光点を配置
- 彗星の尾：同じパスを複製し、移動するダッシュ区間を作る
  （`dasharray = len + " " + (wireLen+200)`、`dashoffset = len - pos`）
- 写真は `clip-path: inset(100% 0 0 0)` → `inset(0)` で下から立ち上げる
- ラベルはタイプライター表示（420ms待ってから45ms/文字。先に `offsetWidth` を固定して幅の揺れを防ぐ）
- ノード：リング（点線・回転）＋コア＋波紋＋スタブ。通過時に `is-lit` が付く
- スクロールは passive + `requestAnimationFrame`、リサイズは150msデバウンスで再構築

### 4-3. 電球型の穴（選ばれる理由）

濃紺の面を電球のシルエットで切り抜き、向こうに灯りのともった住宅街を見せる。

**アセット**：`assets/img/bulb-hole.png`（409KB）/ `.webp`（24KB）、532×918

**生成手順**（`scratchpad/hole.py`）：

1. `denkyuu_real.png`（1024×1536）のアルファチャンネルから電球シルエットを抽出。
   bbox は `(245, 310, 777, 1228)` → 532×918。閾値110で二値化し、0.9pxぼかしてアンチエイリアス
2. 中身は `hero.jpg` の `(670, 470, 866, 808)` をクロップして拡大
   - サイトの色の基準そのものなので紺の面と喧嘩しない
   - ヒーロー動画と同じ場所・同じ日の写真なので景色が繋がる
   - 実写なので「どこの街？」の問題が出ない
   - 下限を y=808 にしているのは、それ以下にベランダの手すりが写り込むため
3. 全体を暗く（Brightness 0.70 / Contrast 1.10）
4. 上に行くほど紺 `(9,24,42)` へ沈める垂直グラデーション（地平線 y=540 基準、指数0.85）。
   穴の上部が背景と同化し、地平線の残照と家々の灯りだけが残る
5. 輝度150以上のみ抽出してブルーム。**窓の灯りだけを光らせる**
   （画像全体をブルームさせると空が白飛びする。一度これで失敗している）
6. 下端（y > 0.70H）を紺に沈めて口金を背景に溶かす。
   これをやらないと、いちばん細いところで明るい家が目立って形の先端に目が行く
7. マスクをぼかしたもの（blur 12）をLUT（`0.24 + 0.76·x^0.45`）で加工し、
   切り口の内側を暗く落として面に厚みを出す。これがないと「写真を切り抜いて貼った」に見える

**CSS**：`.lightband__glow` は「穴から漏れる光」として弱めた（不透明度 .5→.20、blur 20→26px）。
明滅アニメーション `bulbGlow` は削除（穴は明滅しない）。

**未対応**：
- 採用バナーの電球（`denkyuu-real`）はそのまま。ミストグレーの面に載っているので同じ手法が使えない
- 穴のサイズは215pxのまま。背景に穴を開ける仕掛けとしては小さいかもしれないが、
  レイアウトが変わるので勝手に触っていない

### 4-5. endzone（CTA＋フッター）

`aspect-ratio: 1920/852` ＋ `background-size: 100% 100%` で画像を切らずに全部入れる。

## 5. 保留中の構想：電球ポータル

**状態：ユーザーの指示により保留。「後でまた話すかもしれない」**

### 何をしようとしていたか

スクロールで電球の中に視点が入り、街が見え、カメラが上昇して関東圏の俯瞰になり、
そこで対応エリアが文字とともに確認される、という演出。

### 作った動作プロトタイプ

https://claude.ai/code/artifact/e2f74817-8711-4766-a9c2-3546156534ad

sticky ＋ 3.4画面のスペーサー。`clip-path: circle()` で電球のフィラメント位置から穴が開き、
拡大しながらK1〜K4の4キーフレームをスケール＋クロスフェードする。中身は仮画像。
（ソースは `scratchpad/portal.tpl.html` ＋ 画像を data URI に埋める `portal.html` ビルド）

### 議論で出た結論（再開時に読むこと）

- 出口は「街 → 対応エリア」で決定していた。ただし実装するなら
  **「対応可能な工事内容」を電球より前に移す必要がある**。
  いま電球と対応エリアの間に挟まっていて、ポータルが成立しない
- **動画生成AIで1本の動画を作ってそのまま置くのは非推奨。** 理由3つ：
  1. スクロールでのシークが重い（全フレームIフレーム化か画像シーケンスが必要）
  2. 4段のカメラワークを5〜10秒尺で一発成功させるのは博打。
     ヒーロー動画でも「ズームして巻き戻る」事故が起きている
  3. **AIは関東の海岸線を確実に間違える。**
     対応エリアという事実を伝える場所で嘘の絵を出すことになる
- 推奨：生成するのは静止画のキーフレームのみ。
  最後の俯瞰カットは**SVGで1都4県の輪郭と県名をHTMLで重ねる**。
  生成画像は「夜の平野に広がる光」に留めて地理的正確さを主張しない。
  正確さはSVGが担保し、県名はテキストなので編集も読み上げもできる
- プロトタイプを作って判明したこと：**K2（ガラスの内側）は生成不要。**
  電球画像の中身をそのまま引き伸ばすほうが連続性が出る。
  生成が必要なのは K3（街の真上）と K4（上空）の2枚だけ
- 実装上の代償：モバイルで指3回ぶん固定される。スペーサーは2.5画面までに抑えたい。
  `prefers-reduced-motion` ではK1とK4だけを普通に並べる分岐が必須

## 7. 検証環境（再現手順）

```bash
python3 -m http.server 8321
```

Playwright（chromium は `/opt/pw-browsers/chromium`。`playwright install` は不要）で
スクリーンショット・JSエラー捕捉・横スクロール検査。
検査幅は 320 / 390 / 768 / 1440 / 1920。

- ffmpeg は `imageio_ffmpeg.get_ffmpeg_exe()` で取得（apt は使えない）
- 通信スロットリングは CDP `Network.emulateNetworkConditions`。
  パラメータ名は `downloadThroughput` / `uploadThroughput`（`download` / `upload` ではない）
- **コントラスト測定時はテキストを非表示にしてからサンプリングする。**
  描画済みの白文字を含めると数値が跳ね上がる

パフォーマンス推移：857KB / LCP 2124ms（4G）→ 動画追加で 2.02MB / LCP 1720ms
→ バンド写真と重複ポスターの削除で 1.77MB

## 8. 過去にはまった罠

| 症状 | 原因 |
|---|---|
| index.html に孤児マークアップが残った | 非貪欲な正規表現 `<div ...>.*?</div>` が最初の内側 `</div>` で止まった |
| `.page-head > .wrap` が284pxに潰れた | grid item に `margin-inline: auto` → shrink-to-fit。`width: 100%` で解決 |
| page-head の写真が帯を破壊 | 高さ auto の親の中で `<img height:100%>` が自然高にフォールバック |
| フッターのランプが見えない | ①1920px以上で `background-position: left center` が切っていた ②モバイルの32%シフトで画面外 ③均一スクリムが暗い傘を溶かした |
| CTA見出しのコントラストが1.9 | スクリムを濃くするとランプが死ぬので、**元画像をトーンマッピング**（filmic rolloff, T=150 P=2.5）して解決。全ブロック5.0:1以上に |
| パワーラインの写真が見えない | `.powerline__photo` は `<span>`。`display:block` がないと `aspect-ratio` も `clip-path` も効かず高さ0 |
| ナイトゾーンの弧で横スクロール発生 | `width:140%` のはみ出し要素で作っていた。`border-radius: 50% 50% 0 0 / 110px 110px 0 0` に変更 |
| スクロール点灯が「変わったように感じない」 | ①デプロイ待ち ②CSSの10分キャッシュ ③**18%可視で発火 → 画面に入る前に完了していた**（設計ミス） |
| ヒーロー動画が「ダサい」 | 12〜14.9秒で**ズームが巻き戻る**（ビデオの巻き戻しに見える）。クロスフェードもvidstabも失敗し、12.4秒でトリム＋ループ解除で決着 |
| ポスター画像が二重ダウンロード | `poster` にjpg、`<picture>` にwebp。posterもwebpに統一 |
| 穴の空が白飛び | 画像全体にブルームをかけていた。輝度150以上のみ抽出する方式に変更 |
| git が "not a git repository" | 連鎖コマンド内の `cd` で作業ディレクトリが変わっていた |
| ハンバーガーを開くと1項目しか見えない | メニューのパネル（`.header-right`）で基本CSSの `height: 64px` を上書きし忘れ。`box-sizing: border-box` のためパディング160pxが下限になり、160pxの帯に潰れていた。`inset: 0` ＋ `height: auto` で全画面に |

## 9. ユーザーからの指摘の履歴

判断基準として重要なので残しておく。

- 「なんか違うな」— 空室のマンション内観をヒーロー第2画像に提案 → 賃貸内見写真に見える。提案が誤り
- 「変わったように感じないな」— スクロール点灯の発火が早すぎた
- 「確認できた。ただいまいちだな。元に戻して」— スクロール点灯を全面撤回
- 「色を間違えました」— ナイトゾーンはヒーロー/フッターと同じ紺を使う
- 「違うんだよな。スクロールするたびに項目が出てくる感じ」— パワーラインは一括表示ではなくスクロール駆動の蛇行に
- 「この画像拡大してアップするところ、ちょっとダサくない？」— ヒーロー動画のズーム巻き戻し
- 「いまいち動きが予想できないんだけど」— 文章での説明が伝わらず、動くプロトタイプを作って解決

**傾向**：見た目の不満は必ず定量的に原因を特定してから直す
（フレーム単位の追跡、輝度パーセンタイル、ページ幅の実測など）。感覚で当てにいかない。
説明が伝わらないときは、言葉を重ねるより動くものを見せる。
